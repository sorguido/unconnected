The independent reviewer read the canonical governance, inspected the source diff and production layout tests, and independently inspected completed Gradle output and test/lint XML. No device action was performed.

## Outcome and diagnosis

**OBSERVED:** No unresolved blocking source issue was found. The correction is limited to presentation, a small reusable Compose measurement policy, localized error-dialog text, tests and version metadata. The four protected canonical files, screening service, matching/scheduling domain, SettingsStore, settings codec, FilterStatus resolver, contact picking, number-entry validation, manifest and dependency lock are unchanged. The issue #1 observable pause and issue #2 selected-contact logic remain intact.

**PROVEN at source scope:** The previous busy-only progress indicator was a child of the scrolling Column, so insertion/removal changed its measured content height and inter-child spacing. Status title/detail alternatives also have different text lengths and can wrap differently; a fixed real-device pixel displacement from this second mechanism has not been measured. The master button's previous disabled styling could briefly change its color during saving. These mechanisms explain plausible sources of the owner's reported refresh effect; they do not independently establish every cause on the target handset.

## Final implementation checks

- The progress indicator occupies an always-present four-dp overlay at the top of the safe viewport. A permanent four-dp inset before the scrolling modifier keeps even scrolled text below the strip. The indicator is outside the scrolling Column, remains visible when the page is scrolled, has localized saving semantics and a polite live region, and has no pointer-input handler.
- The actual Compose measure policy measures every status alternative at the available width and reserves the maximum resulting height, then places only the selected alternative. The same small policy handles both master-button labels, preventing a longer translated label from increasing button height when only that label wraps. Natural text measurement follows locale, width and font scale; no decorative size animation, fixed text-height cap or ellipsis is introduced.
- Hidden alternatives clear their semantics and are not placed. The selected status uses merged semantics and a polite live region. Only the real selected title/detail and button label should be exposed; native accessibility behavior still needs the owner test.
- SAVING, OFF, ACTIVE, real session pause and missing-permission states retain the existing resolver and copy. The store's pause flow remains observed. Button text/color follow the committed settings; its existing disabled condition and busy save guard are preserved. Disabled colors are held steady only while saving and only if the button would otherwise be usable. An OFF button with missing setup stays visibly disabled.
- Real operation/save errors now use a dismissible Material 3 dialog outside the scroll layout. Error messages and the actual paused state are preserved. This avoids adding/removing an error row during failure/retry and makes errors visible even when the user is far down the page.
- The existing scroll-state instance and save completion sequence are preserved. Legitimate edited content can still grow or shrink, and deleting content can require scroll-range clamping; that is distinct from transient busy-induced movement.

The reviewer raised two additional geometry edges during implementation: the longer master label wrapping at narrow widths/large fonts, and removal/reinsertion of an inline error row during retry. Both are addressed in the final source. The deliberately reserved maximum header space can leave more blank space in short states; this is the tradeoff for stable geometry without clipping long explanations.
