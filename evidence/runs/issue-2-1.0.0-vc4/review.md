## Access, normalization and UI checks

- **OBSERVED:** `ACTION_PICK` uses `ContactsContract.Contacts.CONTENT_TYPE`. The reader accepts only individual local contact/lookup URIs. It rejects directory/query-qualified, collection, unexpected-authority, cross-user and enterprise forms, including encoded enterprise lookup markers. Resolved IDs are checked with Android's enterprise-ID API before reading the name or phone rows.
- **OBSERVED:** Contact metadata has a two-row query bound and must resolve to one valid aggregate. The phone query requests only contact ID, number, type and custom label, with `CONTACT_ID = ?` for that aggregate and a limit of 101. The reader rejects a mismatched contact ID and stops on overflow beyond 100 rows, without returning partial selections. Cursors close on success and failures; cancellation propagates.
- **OBSERVED:** Grouping uses the existing `Numbers.normalize` and complete E.164 keys. Additional digit-preservation checks reject parser repairs such as redundant international trunk zeros. Required Italian `+39`, `0039`, spacing and national forms collapse to one number; different canonical numbers remain separate. Type/custom labels are combined for equivalent rows. Unusable rows produce a clear error or a warning with explicit choice, including when only one safe alternative remains.
- **OBSERVED:** A unique unambiguous number prefills only the editable draft. Multiple alternatives replace the editor with a scrollable Material 3 choice dialog; none is selected by default. Cancel preserves the preceding draft. The selected URI remains saved until selection/cancel, allowing recreation to re-query safely; the draft and editor identity remain saved UI state. IO work belongs to the editor effect and cannot update a dismissed editor after coroutine cancellation.
- **OBSERVED:** Only the editor's Save button invokes `saveNumberEntry`, which applies the existing normalization/duplicate checks before the unchanged persistence callback. Selecting a contact or number does not call the settings store. Both languages contain the new recovery and choice strings, and platform type labels use the activity resources.

Conservative compatibility limits remain intentional: unsupported OEM URI forms, enterprise selections, oversized contacts and representations requiring uncertain digit repair fall back to manual entry. Some less common dialing-prefix forms may also require manual entry; the implementation does not claim universal dialing-format support.
