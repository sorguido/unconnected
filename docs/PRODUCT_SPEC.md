# Product specification — unconnected v1.2

**This is the sole owner of product behavior and acceptance requirements.** The goal is a beautiful, simple, real Android application for anyone who wants to accept calls from selected numbers at chosen weekly times and quietly block those callers outside the permitted hours.

## Acceptance requirements

**R1 — Multiple numbers.** Add, edit, remove and individually enable/disable multiple numbers; optional labels. Support international E.164 normalization and regional numbers with clearly selected/default region; reject invalid or duplicate entries. Evaluate a call only against the caller's complete normalized number, never against a guessed suffix or a silently repaired trunk prefix. No hard-coded business number.

A rule targets either a single number or a bounded numeric range entered in the same field: trailing ASCII asterisks replace the final digits (for example `02 12345***`), up to four of them, in one contiguous run at the end. The app detects which kind was typed. A range is stored as its canonical international prefix plus an explicit wildcard count and matches a caller only when the normalized E.164 value has exactly that prefix and that exact total length, so it is never a free-length prefix rule and its numbers are never enumerated. The deterministic part keeps the Italian geographic leading zero and follows the same lexical rules, normalization and region selection as a single number. The editor shows the number of possible combinations as discreet feedback and requires an explicit confirmation dialog for ranges wider than 1,000 numbers; cancelling it leaves the rules untouched. Only identical canonical targets count as duplicates: a single number inside a range, or two ranges of the same total length, stay savable because every rule shares one calendar with OR semantics. Leading, internal or non-asterisk wildcards, too-short prefixes, totals longer than a full E.164 number and unassignable country codes are refused; an unrecognizable range never blocks a caller.

New-number entry offers native Android `ACTION_PICK` with `ContactsContract.Contacts.CONTENT_TYPE` to choose an aggregated contact. Using the existing READ_CONTACTS permission, read only that contact's name and phone rows through a bounded `Phone.CONTACT_ID = ?` query. Group only proven full-number E.164 equivalents using the existing normalization; retain phone-type/custom labels. One unique, unambiguous number prefills the editor; several distinct numbers require an explicit Material 3 choice. Ambiguous/unusable alternatives are reported, never merged by suffix or silently discarded in an automatic choice. At most 100 phone rows are processed; larger results receive a manual-entry fallback. Enterprise, cross-user and directory selections are not queried.

Selection prefills editable name/number fields and requires explicit Save, using the same normalization/duplicate validation as manual entry. Cancel, no-number results, insufficient permission and unavailable providers leave drafts/rules unchanged; manual entry remains available. No internal address book, synchronization, bulk import, new permission or dependency is introduced. The selected country remains explicit and unchanged.

**R2 — Flexible recurring schedule.** Select weekdays and custom start/end times, with multiple time windows for variable/split shifts, including windows crossing midnight. First-use example may be Monday–Friday 08:30–17:30; everything is editable. Start inclusive, end exclusive. Evaluate in current device local timezone at call arrival, respecting DST, with no alarms or persistent background daemon.

**R3 — Independent schedule and timer controls.** Both functions default OFF at installation. A large green **ACTIVATE SCHEDULE** button enables weekly enforcement and becomes a large red **DEACTIVATE SCHEDULE**. Immediately below it, a matching **ACTIVATE TIMER** / **DEACTIVATE TIMER** button controls temporary blocking independently. Green always proposes activation; red always proposes deactivation. Italian labels are **ATTIVA SCHEDULAZIONE** / **DISATTIVA SCHEDULAZIONE** and **ATTIVA TIMER** / **DISATTIVA TIMER**. Stopping either function preserves the other and all saved rules. Show the schedule state separately from the timer state and remaining time, with truthful role, permission and save-pause status. To bypass all filtering, stop both functions or remove the screening role.

**R4 — Filtering semantics.** Subject to intact general configuration, valid number rules, required permissions and an unambiguous caller, block exactly when `matching_enabled_number AND (timer_active OR (schedule_active AND outside_allowed_hours))`. An active timer overrides every allowed window and works while the schedule is off. At expiry or early cancellation, immediately resume the existing weekly logic without changing its state or windows. Timer activation and operation do not depend on valid or confirmed time windows. Invalid or unconfirmed windows disable weekly enforcement conservatively; corrupt general configuration or number rules still fail open for both functions. Prefer silent disallow with no ringtone or regular missed-call notification where Android supports it. Explicit reject only as tested fallback. Never block unlisted, disabled, hidden, absent, malformed or ambiguous callers. Do not replace the dialer or enable global Do Not Disturb. Android may retain a blocked-call log entry.

**R5 — Onboarding and permissions.** Explain/obtain Android call-screening role; request Contacts permission for screening saved-contact calls when needed; handle refusal and revoked roles without misleading claims. Explain that a forwarded office call may display the ORIGINAL caller instead of the forwarding office number.

**R6 — Finished polished UI.** Real Material 3 interface with coherent visual hierarchy, typography, spacing, useful status, attractive cards, system light/dark modes, sufficient contrast and touch targets, scalable fonts, accessibility and clear empty states. Main screen: master state/button, schedule summary, number list, editing entry points. No inert demo screens. The status card occupies only the natural height of the state actually visible: no space reserved for states that are not shown, no fixed heights, no artificial padding or truncation. Saving must not insert transient rows into the scrolling content and must not replace the card copy with transient text of a different length; progress and the real temporary pause are reported by an accessible non-displacing indicator, while the card keeps the committed state until the operation completes. Keep the scroll state, prevent concurrent edits, and retain truthful paused/error states. Text must adapt to the selected language and font size without truncation. Actual additions/removals and committed state changes may naturally resize the affected card or list; avoid an extra save-induced jump.

**R7 — Internationalization.** Default resources in English, Italian in `values-it/`. Locale follows Android system automatically; every other locale falls back to English. All visible text and errors localized. Respect system 12h/24h time preference.

**R8 — Reliability and state.** All rules remain local and persist across app restarts/reboot. Evaluate at call arrival, not in a persistent worker. `CallScreeningService` must always answer within Android's five-second deadline. Deterministic thread-safe decision and conservative fail-open handling.

**R9 — Privacy.** Offline, no Internet permission without essential justification, no cloud, account, analytics, ads, SMS, recording, logs uploaded or unnecessary contact access. No personal data or secrets committed. Explain stock Android log limitations.

**R10 — Working deliverable.** Reproducible Gradle build, useful automated schedule/number/decision tests, an actual installable APK, real-device call trials, clean installation/uninstallation instructions, and public English docs. The official APK must be signed using the EXISTING signing key from `chromecast-killswitch-app`, never a newly generated one; use unique `applicationId = "it.sorguido.unconnected"`. Verify signer certificate identity and publish checksum/build evidence. No mockups or placeholder functionality count as release.

**R11 — Temporary blocking timer.** Activating the timer opens a dedicated functional screen inspired by the Android Clock timer: hours/minutes/seconds entry with a numeric keypad, 1/5/10/15-minute presets, explicit Start, countdown and early Stop. Accept durations from one second through 99:59:59; reject zero, invalid minute/second fields and larger or overflowing values. The main screen shows temporary blocking and its remaining time without obscuring the independent weekly state. The countdown is presentation only: the screening service evaluates a persisted timer at call arrival even when the UI is closed or its process is recreated. Expiry is exclusive, so no timer block applies at the deadline. Editing the schedule while a timer runs never extends or stops it.

Persist the timer with its original duration, wall-clock start/deadline, elapsed-realtime start/deadline and boot identity. Within the same boot, use elapsed realtime, including device sleep, so manual clock/timezone changes cannot extend the duration. On the first settings read after reboot, use the original wall deadline only while the clock readings remain consistent with the original interval, then atomically save an elapsed-realtime anchor for the new boot. Later clock edits in that boot cannot extend the timer, including after process recreation. Persist expiry observed by a settings read/save as an inactive anchor so it cannot revive after clock rollback; timer edits preserve the latest anchor during unrelated saves. If the anchor cannot be committed, fail open. A wall-clock change before the first observation after reboot cannot be reconstructed reliably without an external trusted clock, so reboot continuation has this stated compatibility limit. Unavailable or inconsistent clock/boot identity also makes the timer inactive conservatively. No permanent service, background polling, exact alarm, new permission or network access is needed.

Schema 3 must read and migrate v1.0.0/schema-1 exact numbers and v1.1.0/schema-2 masks without loss; neither legacy schema implicitly starts a timer. Malformed timer state must never cause unintended blocking. Atomic-save failure pauses both functions for the current app process and reports the recovery path; previously persisted state may return after process restart, as with the existing settings mechanism.

## UX choices

One shared weekly schedule for all enabled numbers; no per-number calendar. A schedule may include multiple named windows. With no configured numbers, no calls are blocked. Enabling enforcement of an empty schedule must clearly warn and request confirmation, since it would block selected numbers all week. Timer activation and cancellation need no empty-schedule confirmation. Show the next allowed interval with local calculation only, clearly distinguishable from the temporary override. Retain stable committed-state presentation during saves and prevent concurrent edits.

## v1 non-goals

Per-number calendars, automatic PBX forwarding changes, identifying forwarding origin when Android exposes only the caller, filtering anonymous numbers, phone system replacement, root hacks, SMS auto-replies, telemetry, cloud sync, call history analytics, and complex rule engines.

## Android constraints

Support Android 10/API 29+ subject to P0 confirmation. Screening role is required; saved contacts may require `READ_CONTACTS`. Do not claim full removal of notification traces or system call history on every OEM. End-to-end behavior and call forwarding must be physically tested.

## Definition of done

V1.2-P1 requires complete implementation, passing automated checks and lint, an actual installable offline Debug APK (`1.2.0-debug`, versionCode 8, `it.sorguido.unconnected.debug`), verified package/version/signature and SHA-256, build evidence, and owner instructions for physical acceptance. Development signing must not use the official private key. The Debug app coexists with the published release and has independent settings; only one app holds the screening role. V1.2-P1 stops at [V1.2-P2 physical acceptance](TIMER_DEVICE_TEST_GATE.md), without official signing, tagging or publication.

Full release acceptance additionally requires real caller, notification, screen-off expiry, process recreation, reboot and UI trials on an identified physical phone. An uninvolved person can install the APK, grant required role/permission, add multiple numbers and masks, set any days/hours, independently start/stop the schedule and timer, observe correct REAL caller behavior, restart/reboot without rule loss, and use Italian or English automatically. Limits are explained. A future official v1.2.0/code-8 release requires separate owner approval and the existing signing identity; v1.1.0 remains intact.
