# P0 — Android feasibility and decision

## OBSERVED
Android exposes `CallScreeningService`, a role-based app interface for handling eligible incoming calls. `CallResponse.Builder` offers disallow, reject and missed-call notification-suppression flags. See C1.

## INFERRED
A native Android Kotlin app with local number list and a rule evaluated at call arrival is sufficient. No alarms, server, rooting, background polling or dialer replacement are needed.

## EVIDENCE_FOR
Official Android APIs support the intended request flags and a five-second screening response contract.

## EVIDENCE_AGAINST
Actual ringing, visual notification, log entry and carrier behavior require on-device tests. Calls from saved contacts may require permission; forwarded calls may present the original caller ID. OEM and Android-version differences exist.

## DECISION
Start with `CallScreeningService` on Android 10+, local storage, strict E.164 matching, `setDisallowCall(true)` + `setRejectCall(false)` + `setSkipNotification(true)` for listed callers outside allowed hours. Fail open on uncertainty. Investigate before attempting fallback explicit rejection.

## OPEN_ITEMS
Confirm platform-specific response behavior on real Android devices; verify forwarding origin visibility; choose number parsing strategy and contact permission UX; verify release signing certificate matches the already-published Chromecast APK.

## GATE
Prior to P1, document API semantics, role/permissions and real-device validation plan; retain signed release checks for P3.

## 2026-10-30 feasibility exit evidence

**OBSERVED:** Official [CallScreeningService reference](https://developer.android.com/reference/android/telecom/CallScreeningService) and [response builder reference](https://developer.android.com/reference/android/telecom/CallScreeningService.CallResponse.Builder) were checked. Incoming eligible calls require a response within five seconds. Contact delivery requires `READ_CONTACTS`; role acquisition uses `RoleManager.ROLE_CALL_SCREENING` on API 29+. Disallow, explicit reject and notification-suppression are distinct response flags. Third-party applications cannot promise removal of blocked call-log entries.

**DECISION:** API 29+ native Kotlin/Compose Material 3; shared immutable rule snapshots stored atomically in a bounded local file. libphonenumber handles region-aware entry validation; incoming IDs additionally require unchanged international digits to prevent parser repair from guessing an identity. Both role and Contacts permission are required to enable enforcement; missing either fails open. A worker computes the response, with a main-handler three-second fail-open budget; actual timing remains a device acceptance item.

**PROVEN:** P0 documentation/implementation-choice exit condition met. [Physical test gate](../DEVICE_TEST_GATE.md) defines the remaining caller, permission, notification, forwarding, lifecycle and UI experiments. [Verification](../../evidence/current/verification.md) owns measured implementation results. No fallback rejection path has been added.
